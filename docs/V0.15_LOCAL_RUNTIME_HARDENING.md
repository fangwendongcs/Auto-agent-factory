# V0.15 Local Runtime Hardening

V0.15 makes local Docker and n8n runtime checks repeatable. It does not enable production autonomous execution.

## What changed

- Added `n8n/compose.local.yml` for a long-running local n8n container.
- Added `npm run runtime:health` for online local n8n health checks.
- Added `npm run runtime:health:offline` for repo-side validation without requiring n8n to be running.
- Added runtime variables to `.env.example` without adding real credentials.
- Added the offline health check to `npm run demo:local`.

## Local n8n startup

Create a local env file from the example:

```bash
cp .env.example .env.local
```

Before storing real n8n credentials, change this value in `.env.local`:

```dotenv
N8N_ENCRYPTION_KEY=replace-with-a-long-local-secret
```

Start n8n:

```bash
docker compose --env-file .env.local -f n8n/compose.local.yml up -d
```

Check the local runtime:

```bash
npm run runtime:health
```

Stop n8n without deleting its data volume:

```bash
docker compose --env-file .env.local -f n8n/compose.local.yml stop
```

## Health check behavior

`npm run runtime:health:offline` verifies:

- compose file exists
- workflow exports exist
- workflow exports are inactive
- expected GoalDriven workflow names are present
- `.env`, `.env.*`, and `.local-audit/` are ignored by Git
- no n8n runtime write is attempted

`npm run runtime:health` additionally probes local n8n using:

- `/healthz`
- `/healthz/readiness`
- `/rest/settings`

The online check is expected to fail if n8n is not running. Use the offline check for CI-like repo validation.

## Import and binding review

After n8n starts, import the workflow JSON files in the documented order:

1. `[GoalDriven] 02 Agent Task Executor`
2. `[GoalDriven] 03 Criteria Checker`
3. `[GoalDriven] 04 Error Handler`
4. `[GoalDriven] 01 Master`

Then manually confirm:

- Master Executor binding points to `[GoalDriven] 02 Agent Task Executor`
- Master Checker binding points to `[GoalDriven] 03 Criteria Checker`
- Master Error Workflow points to `[GoalDriven] 04 Error Handler`
- exported workflow JSON remains inactive in Git

## Safety boundary

V0.15 does not add:

- public webhook exposure
- workflow file writes
- shell execution
- Git modification
- external write actions
- cloud database dependency
- committed credentials

Secrets must stay in `.env.local` or n8n Credentials. Do not paste real API keys into workflow JSON, docs, examples, tests, screenshots, or prompts.
