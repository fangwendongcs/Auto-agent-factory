# V0.19 Action Drafts

V0.19 turns V0.18 human decision records into clearer Codex and GitHub handoff drafts. It remains draft-only: generating a handoff does not execute a retry, modify workflow runtime, write project files, run shell commands, modify Git, deploy, or call external write APIs.

## Goal

Convert local human decisions into handoff drafts that make the next safe step explicit:

- `approved` -> prepare a draft-only handoff, still not automatic execution
- `rejected` -> create a blocked handoff and do not implement
- `needs_review` -> create review questions/checklist and do not implement
- no decision record -> keep the older audit-record review draft behavior

## Current Implementation

- `src/utils/generateActionDraft.js` accepts either:
  - a sanitized audit record
  - a sanitized V0.18 human sign-off decision record
- `scripts/generate-action-draft.mjs` auto-detects the input contract and validates it.
- `examples/action-drafts/sample_v018_rejected_decision_record.json` demonstrates a V0.18 rejected high-risk decision.
- `tests/action-draft.test.js` verifies audit-record compatibility, V0.18 decision conversion, CLI behavior, and secret refusal.

Run the default V0.19 draft:

```bash
npm run action:draft
```

Or pass another sanitized decision record:

```bash
node scripts/generate-action-draft.mjs examples/action-drafts/sample_v018_rejected_decision_record.json
```

## Draft Output

The action draft includes:

- `source_type`
- `human_decision`
- `handoff_status`
- Codex prompt
- GitHub Issue draft
- commit message suggestion
- test commands
- safety block with `draft_only = true` and `write_actions_enabled = false`

For rejected and needs-review decisions, the Codex prompt explicitly says not to implement. For approved decisions, the prompt still says the ledger record is context only and must not be treated as automatic execution permission.

## Safety Boundary

V0.19 does not enable:

- automatic retry
- automatic approval
- workflow runtime modification
- shell execution
- file writes
- Git modification
- deployment
- external write actions
- storing secrets, raw prompts, or raw provider responses
