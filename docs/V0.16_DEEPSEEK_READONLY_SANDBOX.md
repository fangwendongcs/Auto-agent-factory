# V0.16 DeepSeek Read-only Sandbox

V0.16 prepares a real DeepSeek provider sandbox path without enabling write actions. The sandbox sends only a read-only goal payload to local n8n, and only when explicitly enabled.

## What changed

- Added `npm run sandbox:deepseek:readonly`.
- The script builds a safe provider sandbox payload using the existing OpenAI-compatible read-only provider contract.
- By default the script does not send anything. It prints the payload, optional curl command, and sanitized provider run summary.
- Actual POST requires `DEEPSEEK_SANDBOX_SEND_ENABLED=true`.
- Remote webhook POST is blocked by default; local n8n is the expected target.

## Dry-run command

Run without sending:

```bash
npm run sandbox:deepseek:readonly
```

Expected behavior:

- no API key required
- no n8n runtime required
- no provider call made
- payload uses `action_class: read_only`
- payload uses `provider_execution: provider`
- payload requests `real-readonly` provider behavior
- provider run summary is generated in stdout only

## Real local sandbox command

After V0.15 local n8n is running, workflows are imported, and the DeepSeek credential exists in n8n Credentials:

```bash
DEEPSEEK_SANDBOX_SEND_ENABLED=true \
N8N_TEST_WEBHOOK_URL=http://localhost:5678/webhook/<your-local-test-path> \
npm run sandbox:deepseek:readonly
```

Optional local summary artifact:

```bash
DEEPSEEK_SANDBOX_SEND_ENABLED=true \
DEEPSEEK_SANDBOX_WRITE_SUMMARY=true \
N8N_TEST_WEBHOOK_URL=http://localhost:5678/webhook/<your-local-test-path> \
npm run sandbox:deepseek:readonly
```

The optional summary writes only under:

```text
.local-audit/provider-runs/
```

This directory is ignored by Git.

## n8n credential requirement

Create this credential in n8n UI:

```text
goald-openai-compatible-readonly
```

It should hold the DeepSeek Authorization header. The API key must stay inside n8n Credentials, not inside this repository.

Recommended runtime config:

```dotenv
OPENAI_COMPATIBLE_BASE_URL=https://api.deepseek.com
OPENAI_COMPATIBLE_MODEL=deepseek-v4-pro
OPENAI_COMPATIBLE_CREDENTIAL_NAME=goald-openai-compatible-readonly
```

## Sandbox acceptance

A successful V0.16 real local sandbox run should show:

- local n8n receives the request
- Executor resolves provider endpoint and model
- provider call status reaches a response state
- normalized output remains an `agent_result`
- provider mode is `real-readonly`
- output status remains review-oriented, usually `needs_review`
- safety flags do not approve write actions
- high-risk or write-like payloads still require human approval
- no API key appears in stdout, Git diff, workflow JSON, docs, examples, tests, or local artifacts

## Safety boundary

The sandbox script does not:

- store or read provider API keys
- add Authorization headers
- post to remote webhooks unless explicitly overridden
- execute shell commands from model output
- modify Git
- write repo files
- enable external write actions

This is a real provider sandbox only after you explicitly connect it to a local n8n webhook with credentials stored in n8n.
