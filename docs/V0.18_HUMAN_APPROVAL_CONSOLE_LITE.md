# V0.18 Human Approval Console Lite

V0.18 adds a local review console for recovery and high-risk decisions. It is repo-side only and does not connect to n8n runtime, execute retries, approve workflow actions automatically, or enable shell, file, Git, deployment, or external write actions.

## Goal

Provide a small local console that can:

- read a sanitized recovery policy or high-risk review input
- show a reviewable console summary
- accept a human decision: `approved`, `rejected`, or `needs_review`
- record the decision through the existing dev-only sign-off decision ledger
- keep automatic execution disabled

## Current Implementation

- `src/utils/humanApprovalConsoleLite.js` normalizes review inputs and creates sanitized decision records.
- `scripts/run-human-approval-console-lite.mjs` prints the local console output.
- `examples/approval-console/sample_recovery_provider_5xx_review.json` is a safe recovery review sample.
- `examples/approval-console/sample_needs_review_decision.json` is a safe human decision input sample.
- `tests/human-approval-console-lite.test.js` verifies normalization, default no-write behavior, explicit dev-only ledger writes, and secret refusal.

Run the console:

```bash
npm run approval:console
```

By default, this command writes nothing. To explicitly append a dev-only decision ledger entry:

```bash
SIGNOFF_LEDGER_WRITE_ENABLED=true \
SIGNOFF_LEDGER_MODE=dev-jsonl \
SIGNOFF_LEDGER_PATH=.local-audit/signoff-ledger/v018-console-ledger.jsonl \
npm run approval:console
```

The ledger path is restricted to `.local-audit/signoff-ledger/*.jsonl`.

## Supported Inputs

The console accepts two safe input shapes:

- `recovery_policy` wrapper or direct V0.17 recovery policy
- sanitized audit-style high-risk decision input

Recovery policies are projected into sanitized audit records so the existing sign-off ledger contract can be reused without introducing a second approval ledger.

## Safety Boundary

V0.18 keeps:

- local-only execution
- dev-only ledger writes
- no automatic retry
- no automatic approval
- no workflow runtime modification
- no shell execution
- no file write action from workflow
- no Git modification
- no deployment
- no external write action
- no secrets in docs, examples, workflow JSON, or ledger records

`approved` means a human decision was recorded locally. It does not execute the suggested retry or any write action.
